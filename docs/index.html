API de prueba · Tienda y cabinas

Datos inventados para validar que un sistema externo puede consultar y escribir en una API. Los cambios viven en memoria: al reiniciar el servidor vuelven los datos iniciales.

Datos de prueba en archivos fijos (solo lectura)

Estos archivos JSON se pueden leer directo, sin clave y sin que el servidor esté corriendo. Son una copia de los datos iniciales: no aceptan filtros en la dirección ni permiten escribir. Para token, filtros y escritura hace falta la API en funcionamiento.

Rutas de la API en funcionamiento

Cómo autenticarse

Todas las rutas que empiezan con /api/ piden la clave en el encabezado X-API-Key. También se acepta Authorization: Bearer <clave>. La clave está en el archivo .env del proyecto.

Sin clave responden /health, /docs y openapi.json.

Respuestas

CódigoSignifica
200 / 201Correcto / reserva creada
400Falta un dato o tiene mal formato
401Falta la clave o no es válida
404No existe la ruta, la cabina, la reserva o el cliente
405Método no permitido en esa ruta
409La cabina ya está ocupada ese día, o no hay stock suficiente

Los errores siempre traen un campo error con el motivo. Las listas traen total y datos.

Regla de disponibilidad

Una cabina está ocupada en una fecha solo si tiene una reserva Confirmada o ContraEntrega para ese día. Las reservas Pendiente y Cancelada no la ocupan.

Paginación

Todas las listas aceptan limite (1 a 100, por defecto 50) y pagina (desde 1). La respuesta trae total, pagina, limite, paginas y datos.

Reglas de la tienda

  • Los precios están en soles e incluyen IGV (18 %). Cada venta trae subtotal, igv y total.
  • Registrar una venta descuenta el stock; anularla lo devuelve. Registrar una compra lo aumenta.
  • No se puede vender más unidades de las que hay: responde 409.

Cabinas, reservas y clientes

GET /api/cabinas

Lista las cabinas y paquetes.

  • tipo (en la consulta): Opcional. Cabina o Paquete.

Ejemplo: /api/cabinas?tipo=Paquete

GET /api/cabinas/{codigo}

Trae una cabina por su código.

  • codigo (en la ruta): Por ejemplo CAB-001.

Ejemplo: /api/cabinas/CAB-001

GET /api/disponibilidad

Dice qué cabinas están libres en una fecha.

  • fecha (en la consulta): Obligatorio. Formato AAAA-MM-DD.
  • cabina (en la consulta): Opcional. Código de una sola cabina.

Ejemplo: /api/disponibilidad?fecha=2026-12-12&cabina=CAB-001

GET /api/reservas

Lista las reservas.

  • estado (en la consulta): Opcional. Pendiente, Confirmada, ContraEntrega o Cancelada.
  • telefono (en la consulta): Opcional. Teléfono del cliente.
  • fecha (en la consulta): Opcional. AAAA-MM-DD.

Ejemplo: /api/reservas?estado=Confirmada

POST /api/reservas

Crea una reserva en estado Pendiente y calcula el adelanto del 50 %.

Cuerpo JSON de ejemplo:

{
  "cabina": "CAB-002",
  "fecha": "2026-12-20",
  "horas": 2,
  "cliente": "Cliente Prueba",
  "telefono": "51999000009",
  "lugar": "Surco"
}

Ejemplo: /api/reservas

GET /api/reservas/{id}

Trae una reserva por su id.

  • id (en la ruta): Por ejemplo RES-1001.

Ejemplo: /api/reservas/RES-1001

POST /api/reservas/{id}/confirmar

Pasa la reserva a Confirmada. Desde ese momento la cabina queda ocupada ese día.

  • id (en la ruta): Id de la reserva.

Ejemplo: /api/reservas/RES-1002/confirmar

POST /api/reservas/{id}/cancelar

Pasa la reserva a Cancelada y libera la fecha.

  • id (en la ruta): Id de la reserva.

Ejemplo: /api/reservas/RES-1001/cancelar

GET /api/clientes

Lista los clientes.

  • telefono (en la consulta): Opcional. Teléfono exacto, con 51 adelante.

Ejemplo: /api/clientes?telefono=51999000001

GET /api/clientes/{telefono}

Trae un cliente por su teléfono.

  • telefono (en la ruta): Por ejemplo 51999000001.

Ejemplo: /api/clientes/51999000001

Productos

GET /api/productos

Lista los productos con precio, costo y stock.

  • categoria (en la consulta): Opcional. Mochilas, Maletas o Accesorios.
  • marca (en la consulta): Opcional.
  • q (en la consulta): Opcional. Texto a buscar en el nombre.
  • bajo_stock (en la consulta): Opcional. Con 1, solo los que están en su stock mínimo o por debajo.

Ejemplo: /api/productos?categoria=Maletas

GET /api/productos/{sku}

Trae un producto por su SKU.

  • sku (en la ruta): Por ejemplo MOC-001.

Ejemplo: /api/productos/MOC-001

POST /api/productos

Agrega un producto. Obligatorios: sku, nombre, categoria y precio. El resto es opcional y arranca en 0.

Cuerpo JSON de ejemplo:

{
  "sku": "MOC-010",
  "nombre": "Mochila de cuero sintético",
  "categoria": "Mochilas",
  "marca": "Qori",
  "precio": 139.9,
  "costo": 75,
  "stock": 14,
  "stockMinimo": 4
}

Ejemplo: /api/productos

PUT /api/productos/{sku}

Cambia solo los campos que envíes: nombre, categoria, marca, precio, costo, stock, stockMinimo o activo. El SKU no se cambia.

  • sku (en la ruta): SKU del producto.

Cuerpo JSON de ejemplo:

{
  "precio": 149.9,
  "stock": 30
}

Ejemplo: /api/productos/MOC-001

DELETE /api/productos/{sku}

Borra un producto que no tenga ventas ni compras. Si las tiene responde 409: desactívalo con PUT y activo en false.

  • sku (en la ruta): SKU del producto.

Ejemplo: /api/productos/MOC-010

GET /api/categorias

Lista las categorías con su cantidad de productos.

Ejemplo: /api/categorias

Ventas

GET /api/ventas

Lista las ventas.

  • estado (en la consulta): Opcional. Pendiente, Pagada, Entregada o Anulada.
  • telefono (en la consulta): Opcional. Teléfono del cliente.
  • canal (en la consulta): Opcional. WhatsApp, Tienda o Instagram.
  • desde (en la consulta): Opcional. AAAA-MM-DD.
  • hasta (en la consulta): Opcional. AAAA-MM-DD.

Ejemplo: /api/ventas?estado=Pagada&desde=2026-11-01

POST /api/ventas

Registra una venta Pendiente, descuenta el stock y calcula subtotal, IGV y total.

Cuerpo JSON de ejemplo:

{
  "telefono": "51999000001",
  "cliente": "María Quispe",
  "metodoPago": "Yape",
  "items": [
    {
      "sku": "MOC-001",
      "cantidad": 2
    },
    {
      "sku": "ACC-001",
      "cantidad": 1
    }
  ]
}

Ejemplo: /api/ventas

GET /api/ventas/{id}

Trae una venta con sus ítems.

  • id (en la ruta): Por ejemplo VEN-2001.

Ejemplo: /api/ventas/VEN-2001

POST /api/ventas/{id}/pagar

Pasa la venta a Pagada y registra el pago.

  • id (en la ruta): Id de la venta.

Cuerpo JSON de ejemplo:

{
  "metodo": "Yape"
}

Ejemplo: /api/ventas/VEN-2006/pagar

POST /api/ventas/{id}/anular

Anula la venta y devuelve el stock.

  • id (en la ruta): Id de la venta.

Ejemplo: /api/ventas/VEN-2009/anular

GET /api/pagos

Lista los pagos recibidos.

  • venta (en la consulta): Opcional. Id de la venta.
  • metodo (en la consulta): Opcional. Yape, Tarjeta, Transferencia o Efectivo.

Ejemplo: /api/pagos?venta=VEN-2001

Compras

GET /api/compras

Lista las compras a proveedores.

  • estado (en la consulta): Opcional. Recibida o Pendiente.
  • proveedor (en la consulta): Opcional. Id del proveedor.

Ejemplo: /api/compras?estado=Recibida

POST /api/compras

Registra una compra Recibida y aumenta el stock.

Cuerpo JSON de ejemplo:

{
  "proveedor": "PRV-02",
  "items": [
    {
      "sku": "MAL-003",
      "cantidad": 10,
      "costoUnitario": 195
    }
  ]
}

Ejemplo: /api/compras

GET /api/compras/{id}

Trae una compra con sus ítems.

  • id (en la ruta): Por ejemplo COM-3001.

Ejemplo: /api/compras/COM-3001

GET /api/proveedores

Lista los proveedores.

Ejemplo: /api/proveedores

GET /api/proveedores/{id}

Trae un proveedor por su id.

  • id (en la ruta): Por ejemplo PRV-01.

Ejemplo: /api/proveedores/PRV-01

Inventario y reportes

GET /api/inventario/movimientos

Lista las entradas y salidas de stock.

  • sku (en la consulta): Opcional.
  • tipo (en la consulta): Opcional. Entrada o Salida.

Ejemplo: /api/inventario/movimientos?sku=MOC-001

GET /api/reportes/resumen

Totales de ventas, compras e inventario, y los productos más vendidos.

Ejemplo: /api/reportes/resumen
